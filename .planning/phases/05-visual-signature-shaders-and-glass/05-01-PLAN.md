## Objective

Implement the world's visual signature sky shader as a custom TSL NodeMaterial component called `CloudSeaSky`. The shader uses `positionWorld`, `cameraPosition`, `time`, `Fn`, `uniform`, `vec4`, `mix`, `normalize`, and `smoothstep` from `three/tsl` to compute a horizon-gradient sky with animated atmospheric scattering — replacing the flat `<fog>` + `<color attach="background">` approach currently used in `ArchipelagoScene`. Because the project uses `three/webgpu`, TSL compiles to WGSL on WebGPU and GLSL on WebGL2 automatically.

## Capabilities

VIS-01 — Custom TSL sky shader (WGSL/GLSL dual compile via NodeMaterial)

## Delivery scope

- New file `shaders/CloudSeaSky.tsx`: a self-contained R3F component that renders an inside-out sphere (BackSide, no depthWrite) with a `NodeMaterial` whose `colorNode` is a `Fn()`-based TSL function computing a zenith-to-horizon gradient with a slow time-driven hue drift and an animated cloud-sea shimmer band near the horizon.
- `ArchipelagoScene.tsx` modified to: (a) remove `<fog>` and `<color attach="background">` JSX, (b) import and render `<CloudSeaSky>` as the first child, (c) call `assertLightColor` from `lib/colorAudit.ts` inside a `useEffect` for both lights in the scene.

## Verification intent

- Open `/world` in a browser with WebGPU support (Chrome 120+). The sky should show a gradient from a deep blue zenith to a warm orange-pink horizon. It must NOT be the flat `#a8d4f5` color from the previous `color attach="background"`.
- Wait 5–10 seconds. The sky hue should shift subtly (time-driven animation) — the horizon glow should pulse very slowly.
- In DevTools > WebGPU Inspector (or the renderer's `gl.getParameter(gl.VERSION)` on non-WebGPU): confirm the shader compiles. No red screen, no console errors about `NodeBuilder`.
- Switch to a WebGL2 browser (Firefox without WebGPU flag). The sky should render identically in appearance. No console errors. This confirms the GLSL fallback path.
- In dev console, verify no `[colorAudit]` warnings appear for the two lights in the archipelago scene (they use `tokens.scene.sunlight` which is within the palette).

## Technical direction

The new file `shaders/CloudSeaSky.tsx` must follow the import pattern already established in `WorldCanvas.tsx`: THREE classes (specifically `NodeMaterial`) come from `'three/webgpu'`, and TSL function primitives (`Fn`, `uniform`, `vec4`, `float`, `normalize`, `mix`, `smoothstep`, `sin`, `time`, `positionWorld`, `cameraPosition`) come from `'three/tsl'`. The `NodeMaterial` instance and `colorNode` assignment must both be wrapped in a single `useMemo` call — never at module level, because the NodeBuilder is not initialized until R3F mounts the canvas context.

The sky sphere geometry is `<sphereGeometry args={[1, 32, 16]} />` rendered at scale `[500, 500, 500]`. Two properties must be set imperatively on the material ref after creation: `mat.side = THREE.BackSide` and `mat.depthWrite = false`. The `colorNode` is the result of calling the `Fn()`-defined TSL function — this function receives `positionWorld` to compute the elevation angle (dot product of normalized position with world up axis `[0,1,0]`), then blends a `zenithColor` uniform against a `horizonColor` uniform using `smoothstep` and adds a `sin(time * 0.3)` term to animate a horizon shimmer band. Both uniforms are created with `uniform(new THREE.Color(...))` and kept in refs so they do not change identity on re-render.

In `ArchipelagoScene.tsx`, remove the `<fog>` and `<color attach="background">` lines entirely (fog would obscure the sky sphere at distance). Add `import CloudSeaSky from '@/shaders/CloudSeaSky'` and place `<CloudSeaSky />` as the first element inside the fragment. Add a `useEffect` that calls `assertLightColor` from `lib/colorAudit.ts` with both the ambient light color and the directional light color so palette violations are surfaced in dev.
