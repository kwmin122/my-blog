## Notes

### Deviation 1: pnpm create next-app blocked by existing files

`pnpm create next-app@latest . ...` exits with error:
"The directory webbuild contains files that could conflict: .planning/, 2026-04-14-personal-blog-3d-world.md, CLAUDE.md"

The plan acknowledged this risk but expected the tool to proceed anyway. It does not.

**Resolution:** Manually created all Next.js scaffold files (package.json, tsconfig.json, eslint.config.mjs, postcss.config.mjs, app/globals.css, app/layout.tsx, app/page.tsx) with equivalent content to what create-next-app would have produced. The .planning/ and CLAUDE.md files were not touched.

### Deviation 2: next.config.ts required turbopack: {} for Next.js 16

Next.js 16 uses Turbopack as the default bundler. A `webpack` config block without a corresponding `turbopack` config causes a fatal build error:
"This build is using Turbopack, with a `webpack` config and no `turbopack` config."

**Resolution:** Added `turbopack: {}` to next.config.ts. The webpack block is retained as a belt-and-suspenders guard for the webpack fallback path. The three/webgpu alias still works via webpack when Turbopack is not used.

### Deviation 3: next lint command removed in Next.js 16

The `next lint` CLI command does not exist in Next.js 16 (not in `next --help` output). Running `pnpm run lint` with `"lint": "next lint"` returned:
"Invalid project directory provided, no such directory: .../webbuild/lint"

**Resolution:** Updated package.json lint script to `"eslint . --max-warnings 0"`. Also required fixing eslint.config.mjs: the FlatCompat approach caused circular JSON error; replaced with direct `import nextConfig from 'eslint-config-next'` since eslint-config-next 16.x exports a flat config array directly (not an old-style eslintrc config).

### Deviation 4: tsconfig.json updated by Next.js build

During first `pnpm run build`, Next.js automatically updated tsconfig.json:
- `"jsx": "preserve"` changed to `"jsx": "react-jsx"` (required for Next.js)
- Added `.next/dev/types/**/*.ts` to include array

This is expected and intentional behavior. The file change was intentional (Next.js build-time autofix).

### Warning: multiple lockfiles detected

Next.js build outputs a warning about detecting `package-lock.json` at `/Users/min-kyungwook/` (parent directory) alongside `pnpm-lock.yaml` at the project root. This is a cosmetic warning from Next.js 16's workspace root inference. It does not affect the build. Setting `turbopack.root` to the project directory or removing the parent package-lock.json would silence it, but both are out of scope for this plan.
