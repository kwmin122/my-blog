## Objective

Wire the `/world/{slug}` presentation route so it mirrors every post in the MDX pipeline without duplicating content. The world route emits a `<link rel="canonical">` pointing to `/text/{slug}`, passes only the string `title` and `excerpt` to the already-mounted `WorldCanvas`, and renders a floating drei `<Html>` overlay inside the 3D scene showing those two fields — nothing more.

## Capabilities

- **CORE-04**: `/world/{slug}` canonical tag points to `/text/{slug}`; the drei `<Html>` overlay renders title + excerpt only; full MDX body is absent from the world route DOM.

## Delivery scope

- Create `app/world/[slug]/page.tsx` as a server component: `generateStaticParams` (via `getPostSlugs()`), `dynamicParams = false`, `generateMetadata` with `alternates: { canonical: '/text/${slug}' }`, and a page body that imports only `metadata` (never `Post` default export) from the MDX file and passes `slug`, `title`, `excerpt` as props to `WorldPostPanel`.
- Create `components/world/WorldPostPanel.tsx` as a `'use client'` component that receives `{ slug, title, excerpt }` as props, writes them to the `postOverlay` slice in `lib/worldStore.ts` on mount via `useEffect`, and clears the slice on unmount. The component renders no DOM of its own (`return null`).
- Extend `components/world/WorldScene.tsx` to read `postOverlay` from `useWorldStore` and, when non-null, render a drei `<Html>` element (center-anchored, `distanceFactor={10}`, fixed position `[0, 1, -3]`) containing a two-element block: an `<h2>` for the title and a `<p>` for the excerpt. No other MDX content appears inside the Canvas.

## Verification intent

- Human navigates to `/world/sample` in the browser. The persistent WorldCanvas background is visible. A floating overlay panel appears in the 3D scene showing "첫 번째 글" as a heading and the excerpt text beneath it.
- Human views page source of `/world/sample` and finds exactly one `<link rel="canonical" href="https://webbuild-gray.vercel.app/text/sample">` in the `<head>`. There is no `<article>` element and no full post body HTML in the page source.
- Human opens DevTools and searches the DOM of `/world/sample` for the word "이것은 월드에서 탐험할 수 있는" (a sentence from the sample post body). It is not found — only the `excerpt` string appears in the overlay `<p>`.
- Human navigates from `/world/sample` to `/world` (index) and the overlay disappears, confirming the zustand store is cleared on unmount.
- Human navigates directly to `/world/does-not-exist` and sees a Next.js 404, confirming `dynamicParams = false` propagates to the world route.
- `pnpm run build` lists both `/world/sample` and `/text/sample` as statically generated routes.

## Technical direction

The architectural constraint here is that `WorldScene` is mounted inside `WorldCanvas` which lives in the persistent `RootLayout` — it is always in the component tree regardless of which page is active. The world route page cannot render `<Html>` directly because `<Html>` is a drei component that requires an active R3F Canvas context. The solution is the zustand store bridge established in Plan 02-01: `WorldPostPanel` (a `'use client'` component, rendered as a child of the server page) writes to `lib/worldStore.ts`, and `WorldScene` reads from it. This keeps the server page free of any Canvas-context dependency.

`WorldScene.tsx` needs two additions: an import of `Html` from `@react-three/drei` and an import of `useWorldStore` from `@/lib/worldStore`. The existing `useFrame` + `markWorldFirstFrame` logic must remain untouched. The `<Html>` block is guarded by the `postOverlay` nullcheck so it only renders when a world slug is active. The overlay's inline style (`background: rgba(0,0,0,0.7)`, `pointerEvents: 'none'`) is acceptable as a Phase 2 placeholder; visual polish is Phase 5 work.

The `generateMetadata` function in the world route follows the same try/catch pattern as the text route. This prevents build failure if a slug resolves successfully at `generateStaticParams` time but the MDX import fails for any reason. The critical line is `alternates: { canonical: '/text/${slug}' }` — with `metadataBase` set in root layout (Plan 02-01), Next.js expands this to a fully-qualified URL in the rendered `<head>`.
